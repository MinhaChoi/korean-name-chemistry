# 한글 IME 입력 처리

## Decisions

- 실시간으로 글자 단위 판정을 하는 입력 필드는 `onChange`만으로 판정하지 않는다. `onCompositionStart`/`onCompositionEnd`로 조합 상태를 추적하고, 조합이 끝난 시점(음절이 완성된 시점)의 값으로만 게임 로직을 판정한다.
- 입력 필드의 표시값(`value`)은 게임 판정용 상태와 분리한 별도 로컬 state(`displayValue`)로 관리한다. 조합 중에는 `onChange`마다 `displayValue`만 갱신하고, 조합이 끝난 뒤에만 판정용 상태와 다시 맞춘다.

## Boundaries

- 이 규칙은 "사용자가 타이핑하는 대로 매 글자를 실시간 판정해야 하는" 입력 필드에 적용된다. 완성된 문자열을 제출(Enter, 버튼 클릭 등)받는 일반 폼 입력에는 해당하지 않는다.
- 영어 등 조합이 없는 입력에는 영향이 없다. `isComposing` 플래그가 항상 false이므로 기존과 동일하게 `onChange`마다 즉시 판정된다.

## Why

한글은 자음/모음 낱자(예: `ㄴ`, U+3134)와 조합이 끝난 완성형 음절(예: `나`, U+B098)이 서로 다른 유니코드 코드포인트다. `onChange`가 조합 중간 상태(예: 초성 `ㄴ`만 있는 상태)로도 발생할 수 있는데, 이때 `"나무".startsWith("ㄴ")`은 `false`다. "일치하지 않는 입력은 즉시 초기화한다"는 판정 로직을 조합 중간 상태에도 그대로 적용하면, 사용자가 타이핑을 시작하는 족족 입력이 리셋되어 "입력이 안 된다"고 느끼게 된다.

또한 조합 중 판정을 완전히 건너뛰기만 하고 `value`를 판정용 상태에서 그대로 가져오면(둘을 분리하지 않으면), 조합 중에는 그 상태가 갱신되지 않아 입력창이 계속 비어 보이는 별개의 문제가 생긴다. 이래서 표시값과 판정값을 분리하는 두 번째 결정이 함께 필요했다.

## Reconsider when

- Playwright의 `pressSequentially` 같은 자동화 입력은 조합 이벤트를 발생시키지 않고 완성형 문자열을 바로 채워 넣는 것으로 보인다(실제 IME 조합 없이 e2e 테스트가 통과했다). 이 부분을 자동으로 검증하는 e2e 테스트를 추가하고 싶다면, `compositionstart`/`compositionend`를 직접 dispatch하는 방식이 필요하다.

## Evidence worth preserving

- 실제 브라우저에서 `compositionstart` → 조합 중간값(`ㄱ`) → `compositionend`(`과`) 순서로 이벤트를 재현했을 때, 수정 전에는 조합 중간값 시점에 입력이 즉시 초기화되고 표시값도 사라졌다. 수정 후에는 조합이 끝난 음절 단위로만 판정되고, 조합 중에는 표시값이 정상적으로 유지된다.
